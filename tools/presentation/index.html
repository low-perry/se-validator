Catch broken Luigi's Box integrations before the back-and-forth.

SE Validator reads client integration evidence — catalog feeds, frontend HTML/JS, service profiles — and returns a scored, cited report in seconds.

  • Reviewers squint at XML, diff against docs, and miss subtle issues.
  • Every review is a round-trip: client pastes, SE reads, client re-pastes.
  • Severity is inconsistent across reviewers. So is "ready."

One command in. A report with P0 P1 P2 findings, evidence paths, and absolute docs links out.

How it works

Evidence in. Rules and docs. Scored report out.

Evidence
  • Catalog XML / JSON feeds, Content Update payloads
  • Analytics Events API JSON, DataLayer HTML
  • Services Live Autocomplete + Search API probes
  • Frontend Custom Autocomplete / Search UI HTML + JS
→
Validator
  • Deterministic rules Identity uniqueness, required fields, collector placement, analytics parity
  • Doc-aware agent Opens the docs repo, matches sections, cites them inline
  • Optional browser capture Playwright records real network + DOM activity
→
Report
  • Score 0–100, deterministic from findings
  • Findings P0 P1 P2 with evidence + fix + docs
  • Readiness READY RISKY BLOCKED

READY = no P0, no P1. RISKY = P1 but no P0. BLOCKED = any P0. Reviewers can forward the report as-is.

What makes it agentic

The validator doesn't just score — it opens the docs, matches sections, and cites them next to each finding.

  1. 1. Evidence
    Pasted into tmp/agent-input/, or a path inside fixtures/. HTML, JSON, XML, JS.
  2. 2. Deterministic rules
    yarn validate or yarn agent review-* runs the rule set. Each rule fires with priority, fix, and evidence path.
  3. 3. Doc lookup
    For every finding and every detected capability, the agent searches $SE_VALIDATOR_DOCS_ROOT and records the section it matched plus the reason.
  4. 4. Report
    Markdown (for humans / report-viewer) or JSON (for other agents). Docs cited with absolute docs.luigisbox.com links.

Profile generators — intent from live API

HTML alone doesn't say which hit type the client indexed. A live profile captures that intent before anyone opens the file.

1
Input: tracker + query 
yarn suggest search-profile \
  --tracker-id 757876-1071971 \
  --query shirt \
  --filter type:digital-products \
  --out results/search-profile-digital-products-suggested.json
2
Live API probe

Hits search/api/v1/search with the client's tracker ID, counts the hit types returned, records analytics mode from the DataLayer collector probe.

3
Generated profile 
{
  "service": "search",
  "trackerId": "757876-1071971",
  "analyticsMode": "datalayer",
  "features": { "search": "required" },
  "search": {
    "expectedResultTypes": ["digital-products"]
  }
}
4
Fed into the review 
yarn agent review-ui fixtures/frontend/search-bad.html \
  --service search \
  --profile results/search-profile-digital-products-suggested.json \
  --docs "$SE_VALIDATOR_DOCS_ROOT"

This is how the validator catches the classic mismatch — f[]=type:item in the UI when the live Search API returns type:digital-products. The profile knows the ground truth.

Optional: browser-verified with Playwright

Static checks are fast but heuristic. --browser launches a real browser, types a query, and records what actually happens.

    Status — what works, what doesn't, what's next

    Works today
    • Catalog rules for XML, JSON, and Content Update payloads.
    • Analytics checks for Events API + DataLayer collector.
    • Live service probes with profile JSON.
    • Frontend reviews for custom Autocomplete + Search UIs.
    • Profile generators that pull ground truth from live APIs.
    • Doc-aware reports with docs.luigisbox.com citations.
    • Static report viewer for humans, JSON output for agents.
    Known limits
    • Regex detection is file-scoped — a tracker_id in an HTML comment can pass a capability gate.
    • Setter vs reader confusion: assigning item.url in the renderer doesn't prove the click handler reads it.
    • topItems=optional still emits …_NOT_EVIDENCED P2s for integrations that don't need that endpoint.
    • Doc lookup needs a local docs repo; path varies per developer.
    Next
    • Strip comments before capability regex; scope to reader context.
    • Only emit …_NOT_EVIDENCED when the feature is required.
    • Import-parity validator that diffs catalog inputs against Search API responses for each identity.
    • Surface confidence (high / low) when a finding relies on a heuristic flagged as brittle.
    • yarn doctor that prints resolved roots + diagnoses missing docs.
